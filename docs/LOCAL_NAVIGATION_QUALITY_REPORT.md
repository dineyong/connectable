# 로컬 모니터 탐색·키보드 품질 보강

확인일: 2026-10-13. 기존 `monitor-v3` 디자인과 공식 사양·외부 후기 경계를 유지한 좁은 사용성 작업이다. 공개 배포·새 사양·추천·댓글·전체 사용자 집계를 추가하지 않았다.

## 실제 재현 및 수정

| 항목 | 수정 전 8875 로컬 UI 재현 | 수정 |
| --- | --- | --- |
| 빈 결과 초기화 | 없는 모델 검색 후 `필터 초기화`를 실행하면 빈 결과 패널이 숨겨지면서 포커스가 body로 사라졌다. | 초기화 후 모델 검색창으로 포커스를 복귀한다. 다시 키보드 입력을 바로 할 수 있다. |
| 데스크톱 비교함 제거 | 비교함에서 첫 제품을 제거하면 남은 비교함 제품 대신 방금 제거한 제품의 목록 카드로 포커스가 이동했다. 목록 위치에 따라 예상하지 못한 스크롤 이동도 발생할 수 있었다. | 남은 비교함의 제거 버튼을 우선 선택하고, 마지막 항목 제거 시 `모니터 골라 비교하기`로 복귀한다. 목록 카드에서 선택할 때는 기존 카드 포커스를 유지한다. |

비교 선택 다이얼로그 → 결과 다이얼로그 → Escape 복귀는 기존 구현에서 `compare-start`로 정상 복귀했다. 해당 흐름은 변경하지 않았다. 모바일 비교함은 기존대로 개별 제거 버튼을 숨기므로 `비교함 비우기`를 사용하며, 이 버튼의 기존 복귀 동작도 유지했다.

## 검증

실행 중인 `http://127.0.0.1:8875/monitor-v3.html`에 별도 Playwright 브라우저로 접속해 데스크톱 1440px·모바일 390px에서 실제 DOM 동작을 확인했다. 별도 서버나 전체 e2e 실행은 이 세션에서 시작하지 않았다.

- 수정 전: 빈 결과 초기화 시 body 포커스, 비교함 제거 시 제거제품의 목록 카드 포커스 재현.
- 수정 후: 두 화면 폭 모두 빈 결과 초기화 후 `monitor-search` 포커스 확인.
- 데스크톱: 남은 비교함 버튼 포커스와 마지막 제거 후 `compare-start` 복귀 확인.
- 모바일: 비교함 전체 비우기 후 `compare-start` 복귀 확인.
- [브라우저 회귀 테스트](../tests/e2e/monitor-navigation-focus.spec.js)에 위 흐름 두 가지를 추가했다. 두 프로젝트에서 모두 실행하며 모바일을 skip하지 않는다.
- 전체 Python·브라우저 실행 및 CI는 통합 세션 결과를 따른다.

## 변경·보존 범위

변경은 [모니터 UI 스크립트](../web/monitor-v3.js)의 두 포커스 처리와 새로운 회귀 테스트뿐이다. 원본 사양, 미확인 값, 필터 조건, 후기 URL·모델 연결 가드, 비교 저장 계약, 디자인 HTML/CSS를 변경하지 않았다. 사용자 작업인 `README.md`, `docs/DECISIONS.md`, `web/site-v2.js`, `tests/e2e/content-review.spec.js`는 수정하지 않았다.

추가 승인 필요 항목은 없다. 포커스 동작 외의 전체 접근성·데이터 정확도는 이 소규모 검수만으로 보장하지 않으며 통합 테스트와 기존 데이터 검증을 유지해야 한다.
