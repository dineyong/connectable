## 첫 출시에서 권장하는 편집 흐름

1. **모니터 본제품의 신규 발표·한국 출시·가격/판매 일정**을 우선하고, 패널 기술·주변기기 소식은 보조 항목으로 둔다. 휴대폰 사전예약은 별도 분류로 유지한다.
2. RSS·검색 API는 후보 발견만 수행한다. 제품명·출시 지역·날짜는 공식 원문 본문을 열어 확인한다. 원문 접근 실패나 모델 불명은 보류한다.
3. 모델별 발표와 제품 사양 기준 원본을 분리한다. 발표 기사 하나를 근거로 해당 제품의 모든 사양·한국 SKU·현재 재고·호환성을 승인하지 않는다.
4. 같은 발표를 인용하는 여러 기사는 독립 발표 수로 세지 않는다. 공식 발표 URL을 중심으로 묶고, 서로 다른 지역의 출시 일정은 합치지 않는다.
5. 기사별 사용 조건을 확인한 뒤 검토 대상에 올린다. 공개 RSS 제공, 검색 결과 API 제공, 공식 제조사 소식이라는 이유만으로 상업적 전재권을 확보했다고 기록하지 않는다.
6. 첫 운영은 검토 후 정적 목록 갱신을 권장한다. 모든 미확인 이용 조건을 해결하거나 상시 갱신을 구현하기 전에도 모니터 비교 핵심 사이트 준비는 계속할 수 있다. 공개 조건을 충족하지 못하는 뉴스 항목은 별도 보류한다.

### 최소 표시 형식

- 사실 중심의 짧은 식별 제목, 출처명, 발표 지역, 게시 날짜, 직접 확인 날짜, 원문 링크.
- 원문 전체·긴 문단·썸네일·작성자 개인정보는 저장하지 않는다. 현재 뉴스 스키마도 본문/이미지 필드를 허용하지 않는다.
- RSS 제목 그대로 표시하는 기존 방식은 이용 조건을 검토한 항목에 한정한다. 본문 확인 후 작성한 짧은 사실 설명과 원문 그대로의 제목을 구별한다. 번역·AI 생성 요약을 검수된 원문 사실처럼 표시하지 않는다.
- 링크는 새 창/탭, `noopener noreferrer`로 유지하고 사용자에게 원문 이동을 알린다.
- ‘출시 발표’와 ‘지금 구매 가능’, ‘발표된 사전예약 날짜’와 ‘현재 예약 중’을 구분한다. 시간대·판매처·종료 시각·최신 재확인이 없으면 진행 중 배지를 자동 생성하지 않는다.
- 오래된 항목은 마지막 확인일을 그대로 표시한다. RSS 접근 성공만으로 본문 내용·판매 상태 확인일을 갱신하지 않는다.

이 형식은 복제량과 오해를 줄이기 위한 운영안이다. 모든 출처의 상업 사용 권리가 확정됐다는 결론은 아니다.

## 아직 결정하거나 운영 환경에서 확인할 사항

- 도메인·호스팅 결정 이후 접근 제한 미리보기에서 실제 자산·404·보안 헤더를 확인한다. 실제 공개 승인 전에는 noindex를 유지한다.
- 뉴스 이용 조건이 확인된 항목의 공개 검토와 삭제/정정 요청 처리 담당이 필요하다. 기존 기사의 승인 보류를 이번 조사로 해제하지 않는다.
- 운영 빈도·보존 기간·장애 알림·API 사용은 후속 결정이다. 초기는 수동 검토 갱신을 권장하며 새로운 스케줄러나 계정을 만들지 않았다.
- 모니터 중심 목록의 정보량은 부족하다. 향후 수집을 하더라도 공식 발표 소수를 먼저 검토한다. 전 제품·전 매체 대량 뉴스 수집은 출시 필수 조건이 아니다.
- 확인된 요약과 불확실한 출처를 한 상태로 합치지 않는다. 원본 스키마나 공개 검토 정책을 뉴스 UX 개선을 이유로 완화하지 않는다.

## 이번 작업의 산출물 및 보존

변경은 이 보고서뿐이다. 뉴스 30건·공식 발표 2건·파생 JS·수집 코드·정적 사이트·사양 원본은 보존했다. 외부 열람 결과를 신규 뉴스 행으로 입력하지 않았다. [로컬 뉴스 보강 기록](LOCAL_NEWS_COMPLETION_REPORT.md), [첫 출시 준비 기록](FIRST_RELEASE_PREPARATION_REPORT.md)을 과거 검증 결과와 혼동하지 않는다.
