# 외부 후기 링크 통합 후 읽기 QA

확인일: 2026-10-13. 검토 기준은 후기 배치 5 `3954e15`의 현재 파일이다. 이번 세션은 원문을 다시 조회하거나 원본 자료·코드·승인 상태를 수정하지 않았다. 전체 테스트와 서버 시작은 통합 세션이 담당한다.

## 대조 결과

[배치 5 보고서](MONITOR_REVIEW_LINK_BATCH_5_REPORT.md) 및 [플랫폼 계약](MONITOR_REVIEW_LINK_PLATFORM_REPORT.md)을 기준으로 [원본](../data/research/monitor-review-links.json), [공개 파생 자료](../data/site/monitor-review-links.json), [생성 JS](../web/monitor-review-links-data.js), 정적 30개 상세 문서, 동적 렌더 함수를 비교했다.

- 원본과 공개 자료의 공개 필드가 일치하며 생성 JS는 공개 JSON과 동일하다. 생성기 `build()`의 현재 결과와 공개 JSON도 동일하다.
- 30개 정적 상세 문서의 후기 URL 목록·순서·제목·요약·확인일이 제품별 공개 자료와 일치한다. 모든 후기 링크에 `_blank` 및 `noopener noreferrer`가 있다.
- 현재 동적 `externalReviews` 함수를 읽기 검증용 Node VM에서 실행한 결과 30개 제품 모두 공개 데이터의 해당 제품 후기 수와 동일했다.
- 총 34개 링크·28개 제품이다. RTINGS 5, Quasarzone 1, YouTube 20, Blog 6, Tistory 1, Forum 1이다.
- `34WQ75C-B.AUS`, `S65UC (LS34C650UEEXXY)`는 실제 연결 링크가 없으며 다른 모델 후기를 빌려 표시하지 않는다.

## 실제 로컬 화면 확인

최초 `http://127.0.0.1:8875/monitor-v3.html` 접속은 `net::ERR_CONNECTION_REFUSED`였다. 통합 세션이 기존 미리보기 서버를 복구한 뒤 새 임시 탭에서 다시 확인했다. 검토가 끝나면 해당 임시 탭을 닫았으며 사용자 탭은 건드리지 않았다.

1. 삼성 `S32CG554EU (LS32CG554EUXEN)` 상품 상세를 실제 버튼으로 열었다. ComputerBase 원글 1개, `커뮤니티 · 개인 사용기`, 확인일 2026-10-13, 잔상 관측 요약 및 광고·판매·제휴 요소 표시가 정상적으로 나타났다. 해당 링크의 실제 DOM 속성은 `_blank`, `noopener noreferrer`다. 외부 목적지는 이번 QA에서 열지 않았다.
2. LG `34WQ75C-B.AUS` 상품 상세의 실제 빈 상태를 확인했다. 다른 LG 후기는 나오지 않았다.
3. 삼성의 정적 상세 페이지에서도 같은 후기 카드·출처 종류·확인일·요약이 표시됐다.
4. 확인한 로컬 화면의 콘솔 error/warn은 없었다. 이 결과는 해당 화면을 확인한 범위이며 전 페이지 네트워크·모바일 검사를 대신하지 않는다.

## 발견한 방어 경계 차이 — P2

현재 정상 데이터에서 잘못 연결된 후기를 발견하지 않았다. 다만 [동적 표시 코드](../web/monitor-v3.js)의 RTINGS/Quasarzone 링크 검사는 정확한 제품별 근거 바인딩보다 느슨하다. 신규 YouTube·블로그·Forum은 파생 `reviewed_bindings`를 확인하지만 RTINGS는 호스트와 `/monitor/reviews/제조사/모델` 형식만 확인한다. 원본 생성기는 RTINGS 제품별 고정 경로를 검사한다.

재현:

1. 공개 JSON에서 RTINGS M32U 항목을 복사한다.
2. `product_id`만 `monitor:dell-u2724d`로 변경하고 URL은 M32U 그대로 둔다.
3. `window.CONNECTABLE_REVIEW_LINKS`에 해당 항목 1개가 있는 입력을 가정하여 현재 `externalReviews({id: 'monitor:dell-u2724d'})`를 실행한다.
4. 반환 HTML에 M32U RTINGS URL이 포함된다. 읽기 검증용 VM에서 결과 `true`를 확인했으며 저장된 파일이나 브라우저 공개 자료는 변조하지 않았다.

원본 생성기를 거치면 같은 잘못된 연결이 거부된다. 따라서 원본→검증→생성 경로의 현재 자료는 정상이나, 독립적으로 파생 자료가 잘못 편집되거나 변조됐을 때 화면의 방어 수준이 일치하지 않는다. Quasarzone도 화면에서는 제품별 원본 참조 재확인을 수행하지 않으므로 같은 범주의 검토 대상이다. 이번 QA는 임의 수정을 하지 않고 통합 세션에 재현을 전달했다.

## 테스트 빈틈과 표현상 제한

[브라우저 테스트](../tests/e2e/monitor-review-links.spec.js)는 악성 URL, 모호한 모델 상태, 새 창/opener 분리, 신규 플랫폼 등록 누락을 검증한다. 검토 당시 RTINGS의 정상 문법을 유지하면서 다른 제품으로 연결하는 파생 입력을 거부하는 회귀가 없었다. 이 경계 수정 시 정상 연결과 교차 모델 연결을 함께 검증해야 한다.

광고 표시는 사이트 운영 광고와 작성자 협찬·제휴를 하나의 넓은 상태로 표현한다. ComputerBase의 표시 `광고·판매·제휴 요소 있음`은 사이트 배너 존재와 일치하지만 작성자 협찬이 확인됐다는 뜻은 아니다. 자세한 구분은 원본 notes에 남아 있고 공개 카드에는 포함되지 않는다. 잘못된 협찬 확정 표현은 발견하지 않았으나 공개 운영 전에는 이 범위를 설명하면 오해를 줄일 수 있다.

해외 언어·지역 후기 및 부분 공개 전문 리뷰는 원본 메모의 확인 범위 내 링크이며 한국 SKU 동일성이나 호환성 승인으로 승격되지 않는다. 이번 QA에서 원문을 재확인하지 않았으므로 링크의 현재 접근 가능성·삭제·리다이렉트·후기 품질은 새로 승인하지 않는다.

## 후속 처리

위 P2 재현은 수정 전 코드 기준이다. 통합 세션은 모든 플랫폼의 정확 제품·사이트·URL 바인딩을 파생 자료와 동적 표시 양쪽에 적용하는 최소 수정 및 회귀 검증을 진행한다. 수정 후 결과와 전체 테스트·CI는 [후속 통합 보고서](REVIEW_LINK_COMPLETION_AND_LOCAL_READINESS_REPORT.md)에서 확인한다. 이 QA 세션은 수정 전 발견과 정상 실화면 확인까지만 담당했다.
