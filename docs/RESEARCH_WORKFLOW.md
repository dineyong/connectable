# 조사 및 데이터 수집 절차

- 문서 상태: Baseline v1
- 확정일: 2026-10-07

## 1. 목적

개발 전에 실제 사용자 문제, 공식 제품 사양, 인터페이스 규격, 실사용
결과를 재현 가능한 방식으로 수집한다. 조사 결과는 대화에만 남기지 않고
CSV 또는 Markdown 파일로 버전 관리한다.

## 2. 작업 순서

1. 실제 사용자 질문 수집
2. 질문의 제품 모델과 문제 유형 표준화
3. 공식 제조사 사양 확인
4. 관련 표준·인증 문서 확인
5. 실사용 성공·실패 사례 교차 확인
6. 데이터 신뢰등급 부여
7. 판정 규칙 후보 작성
8. 모순·결측치 검토
9. 검수 후 초기 데이터에 반영

## 3. 출처 등급

| 등급 | 출처 | 허용 용도 |
|---|---|---|
| A | 제조사 공식 제품 사양, 공식 매뉴얼, 표준기관 문서 | 핵심 판정 근거 |
| B | 공식 지원 답변, 인증 데이터, 복수의 일치하는 실사용 사례 | 보조 판정·검증 |
| C | 단일 커뮤니티 글, 전문 매체 리뷰, 개인 블로그 | 질문 발굴·참고 |
| D | 쇼핑몰 상품 설명, 판매자 답변, 출처 불명 요약 | 제품 후보 발굴만 허용 |
| X | AI가 출처 없이 생성한 정보 | 판정과 데이터 입력에 사용 금지 |

## 4. 출처 기록 필드

모든 사양 근거는 최소한 다음 필드를 가진다.

- `source_id`
- `source_url`
- `source_title`
- `publisher`
- `source_type`
- `reliability_grade`
- `accessed_at`
- `published_or_updated_at`
- `applies_to_model`
- `claim_summary`
- `quoted_fragment_or_location`
- `archived_or_snapshot_reference`
- `review_status`
- `review_notes`

원문 전체를 무단 복제하지 않는다. 판정에 필요한 사실과 원문 위치만
기록한다.

## 5. 사용자 질문 수집 규칙

### 포함

- 구체적인 기기 또는 규격이 언급됨
- 원하는 결과나 문제가 식별됨
- 연결 방식 또는 증상이 설명됨
- 실제 구매·연결 의도가 있음

### 제외

- 제품 홍보만 있는 글
- 모델과 문제가 모두 불명확한 글
- 동일 글의 복제본
- 개인정보가 포함된 내용
- 접근 제한을 우회해야 확인할 수 있는 내용

### 익명화

- 사용자명, 이메일, 전화번호, 주문번호를 저장하지 않는다.
- 질문 본문 전체 대신 문제를 요약한다.
- 원문 URL과 게시일은 검증 목적으로 보관한다.

## 6. 공식 데이터 수집 규칙

- 모델명과 하위 모델 번호를 분리한다.
- 국가별 사양 차이를 기록한다.
- 같은 제품명이더라도 출시 연도와 칩셋이 다르면 별도 모델로 관리한다.
- `USB-C`라는 명칭만으로 영상 출력 또는 PD 지원을 추정하지 않는다.
- 최대 해상도와 주사율은 동시 조건을 함께 저장한다.
- 독·허브는 호스트 운영체제별 출력 제한을 구분한다.
- 소프트웨어 드라이버가 필요한 기능은 네이티브 출력과 분리한다.

## 7. 모순 처리

출처가 충돌하면 임의로 하나를 선택하지 않는다.

1. 모델 번호와 지역이 동일한지 확인한다.
2. 문서의 갱신일과 펌웨어·운영체제 조건을 확인한다.
3. 제조사 사양과 공식 지원 문서의 차이를 기록한다.
4. 실사용 사례가 동일한 케이블과 설정인지 확인한다.
5. 해결되지 않으면 `CONFLICT` 또는 `UNKNOWN`으로 유지한다.

## 8. 자동화 허용 범위

### 허용

- 공개 페이지 URL 목록화
- 문서 변경 감지
- 모델명 정규화 후보 생성
- 중복 질문 탐지
- 단위 변환과 대역폭 계산
- 누락 필드 검사
- 공식 URL 상태 확인

### 사람 검수 필수

- 제품 모델 최종 식별
- 사양 사실 확정
- 충돌 출처 해석
- 호환성 최종 판정
- 사용자 사례 공개 승인
- 제휴상품 추천

### 금지

- 접근 제한 또는 차단 우회
- 로그인 세션의 무단 자동수집
- 서비스 약관을 위반하는 대량수집
- 출처 없는 AI 생성값의 데이터베이스 입력

## 9. Git 작업 규칙

- 조사 단위별로 작은 커밋을 만든다.
- 원본 자료와 정제 데이터를 구분한다.
- 출처 없이 사양값만 변경하지 않는다.
- 판정 규칙 변경에는 영향을 받는 테스트 케이스를 함께 추가한다.
- 비밀키, 계정정보, 개인 데이터는 커밋하지 않는다.
- 대용량 원문 복제 대신 출처와 필요한 사실만 저장한다.

권장 커밋 예시:

```text
docs: define MVP product scope
research: add 20 Mac display questions
data: add official display specs for MacBook Air M1
rules: document native external-display limits
fix(data): correct monitor PD output with source
```

개발 착수 전에 최소한 다음 조건을 충족해야 한다.

- A등급 공식 출처 목록
- 초기 맥북 모델의 공식 사양 수집
- 초기 모니터 30개의 공식 사양 수집 가능성 확인
- 판정 규칙의 핵심 변수 정의
- 모순과 결측 데이터를 표현하는 방법 확정
- 초기 조합 테스트 케이스 30건
