# Connectable 제품 방향 v2 및 세션 작업 기준

## 목표

맥북과 함께 사용할 모니터를 찾는 사람이 공식 기능과 실제 사용자 후기를 비교해 선택하는 한국어 구매 가이드와 연결 후기 사이트를 만든다. 정보성 콘텐츠로 방문을 유도하고 애드센스와 쿠팡파트너스 수익화를 준비한다. 수익 보장이나 광고 계정 승인 완료를 의미하지 않는다.

## 첫 구현 범위

홈의 흐름은 모니터 탐색 카드 → 연결 후기 → 구매 전 연결 가이드다. 맥북 모델·용도·기능별 탐색, 모니터 상세의 공식 부가기능과 출처, 구성별 실제 관측·불편·결측, 가이드와 관련 콘텐츠 연결을 제공한다. 제휴 고지와 분리된 광고 자리만 준비하며 실제 광고 코드·미승인 제휴 URL·구매 링크를 만들지 않는다. 후기는 초기에는 기존 공개 자료의 출처 있는 편집 요약이다. 댓글·회원가입·후기 제출 서버·자유 게시판은 이번 구현 범위에서 제외한다.

## 보존과 정확성

기존 질문 v1/v2, 영어 예시, 공식 catalog, 연구 pilot, Path Instance, 골든 계획, 검증기·테스트·조사 보고서를 삭제하지 않는다. 기존 web도 교체 전 별도 보존본을 만든다. 신규 화면용 데이터는 data/site/에 별도 파생 자료로 둔다. 공식 기능과 사용자 보고를 분리하고, 사용자 성공을 전체 제품 호환 승인으로 바꾸지 않는다. 미검증은 UNKNOWN/검토 중으로 표시한다. 비공개 사용자 대화는 공개 자료로 편입하지 않는다. AI 이미지나 예시 제품을 실제 제품 사진·후기로 게시하지 않는다. 기존 복잡한 판정 엔진 확장·추가 대량 수집은 우선순위에서 보류한다.

## 세션 분담과 파일 소유

| 세션 | 소유 파일 | 업무 |
|---|---|---|
| 현재: 기획·진행 관리 | README.md, docs/DECISIONS.md, 이 문서 | 방향 확정·의존성·통합 검토 |
| 데이터·콘텐츠 | data/site/, docs/SITE_CONTENT_V2_REPORT.md, scripts/build_site_content_v2.py, tests/test_site_content_v2.py | 기존 근거로 모니터·후기·가이드 표시 데이터 구축 |
| 사이트 화면·기능 | web/, docs/SITE_V2_IMPLEMENTATION_REPORT.md, tests/e2e/site-v2.spec.js | 승인 목업 구현·데스크톱/모바일 검증·기존 화면 보존 |
| 품질·검색·수익화 | docs/SITE_V2_QA_MONETIZATION_PLAN.md | 사전 검토·최종 품질 체크리스트·검색/광고/제휴 준비 |

모든 세션은 README·관련 docs와 기존 변경사항을 먼저 읽는다. 서로 소유 파일을 수정하지 않는다. 동일 checkout을 공유하므로 브랜치 전환·reset·stash·정리·삭제·Git index 조작·commit·push는 담당 세션에서 하지 않는다. 현재 세션에서 변경을 모아 검증한 뒤 Git 마무리를 조율한다. main merge와 배포는 하지 않는다. 기존 미커밋 변경을 자신의 작업으로 취급하지 않는다.

## 데이터와 화면 계약

데이터 세션은 data/site/content-v2.json을 기준으로 작성한다. 최상위 schema_version, generated_on, monitors, reviews, guides, disclosures를 둔다. 각 콘텐츠는 안정적인 id, title, source_refs, review_status를 가진다. monitors는 확인된 표시 모델과 기능, reviews는 monitor_ids(미상은 빈 배열), 맥북 표시명·연결 요약·관측·결측, guides는 본문과 관련 ID를 제공한다. 원문 내용 복사·닉네임 저장·미확인 사양 보완은 금지한다. 먼저 기존 자료에서 표현 가능한 만큼만 만든다.

화면은 위 JSON을 로컬 fetch로 읽으며 기존 서버의 connect-src none 정책을 보안 약화로 변경하지 않는다. 필요한 경우 화면 세션이 정적 JS 파생 자산을 만들어 로드한다. 데이터 완성 전에는 예시 표시를 명시한 빈 상태로 레이아웃을 만들고 실제 추천·통계를 꾸미지 않는다. 구체 계약 확장이 필요하면 보고서에 기록한다.

## 진행 순서와 완료 기준

기획 확정 후 데이터와 화면 세션이 병행한다. 품질 세션은 먼저 기존 자료를 읽고 사전 체크리스트만 만든다. 실제 화면·데이터 완료 후 현재 세션이 품질 세션에 통합 검증을 요청한다. 방문자가 후보를 탐색하고 기능·후기를 비교하고 구매 전 확인점을 이해할 수 있어야 한다. 기존 데이터·테스트 보존, 출처·UNKNOWN 표시, 모바일·키보드·빈 상태·내부 링크를 검증한다. 광고·제휴 계정 연결은 별도 실제 승인 확인 단계다.

## 2026-10-09 승인된 후속 배치

사용자가 벤치마크를 참고한 후속 실행을 승인했다. 기존 공개 후기에서 식별되는 모니터3~5개를 공식 제조사 자료에 연결하고, 출처 있는 기능/후기를 상세에 함께 표시한다. 자료를 확보하지 못하면 숫자를 억지로 채우지 않는다. 데이터 담당은 data/site/에 조사 근거를 별도 보존하고 신규 SITE_CONTENT_MONITOR_BATCH_1_REPORT.md를 작성한다. 화면 담당은 archive/site-v2-20261009/로 직전 화면을 보존한 뒤 읽기 쉬운 카드·상세, 공식 기능 필터, 두 제품 비교, 가이드 요약·목차·관계 링크를 구현한다. 품질 담당은 완성 후 후속 통합 검수를 수행한다. Windows 확장·회원/댓글·실제 광고/제휴·공개배포는 이번 범위에서 제외한다. 기존 검토 상태·원본·부분결측은 유지한다.
