## 공개 전 남은 기술 작업과 위험

### 필수 — 아직 공개 가능한 최종 빌드가 아님

1. **최신 SHA를 비공개 검수본에 반영하고 운영 안내를 다시 확인해야 한다.** 현재 로컬/CI 성공과 예전 원격 성공은 서로 다른 버전이다.
2. **초안을 적용하는 공개 전용 출력물과 검증을 만들어야 한다.** 현재 생성기는 noindex·robots 전체 차단·검수 안내를 그대로 유지한다. canonical/robots/사이트맵/헤더/리다이렉트는 `activation-drafts/`에만 존재한다. 초안 복사만으로 끝나는 작업이 아니며, 모든 페이지의 metadata·검수 문구와 공개 헤더를 일관되게 전환해야 한다. 운영 주소가 contact라는 이유로 자동 승인해서는 안 된다.
3. **공개 CSP 적용 상태의 브라우저 검증이 필요하다.** 현재 전체 e2e는 로컬 개발 서버이며 공개 `_headers.proposed`가 적용된 응답을 검사하지 않는다. 공개 출력의 JS·CSS·대화상자·저장 기능이 동작하는지 별도로 확인한다.
4. **승인된 공개 후보 SHA·manifest를 고정한 뒤 최종 사용자 승인을 받는다.** 그 다음에만 Cloudflare production/도메인/HTTPS/대표 호스트 이동을 적용하고 실제 origin의 200/404/헤더/캐시/색인을 재검사한다. 공개 승인은 main merge 승인과 별개다.
5. **실제 운영·보안 정보 안내를 확정한다.** 현재 운영 안내에는 공개 전 실제 로그 설정에 맞춰 확인한다는 문구가 남아 있다. 공개 출력에서는 사용하는 서비스와 문의 메일 처리 범위를 실제 운영 설정과 대조해야 한다. 법적 완결성을 이번 테스트로 보장하지 않는다.

이들은 배포 전환의 미완료 작업이다. 지금 그대로 게시해도 된다는 판정은 아니다. 현재 manifest의 `FINAL_PUBLICATION_APPROVAL_PENDING` 하나는 사용자 승인 상태를 나타낼 뿐 위 기술 작업 전체의 완료 증명서가 아니다.

### 유지하거나 후순위로 둘 항목

- 한국 SKU·일부 사양·공식 충돌은 기존 사용자 결정대로 명시하여 제공할 수 있다. 전부 채우기 위해 다시 대규모 수집할 필요가 없다.
- 외부 후기 원문의 삭제·수정·리다이렉트·지역별 차단은 계속 발생할 수 있다. 이번에는 35개 원문과 전체 제조사 페이지의 최신 사실을 모두 재확인하지 않았다. 기존 검증은 저장된 근거/모델 연결과 URL 계약을 확인하며 실시간 가용성을 보증하지 않는다.
- 모바일 검수는 Chromium 기반 iPhone 뷰포트다. 실제 iOS Safari·저사양 기기·사용자 보조기기의 전수 검수가 아니다. 실기기 한 번 확인을 권장한다.

- 사진, 분석 도구, 쿠팡/광고, 공개 댓글·반응 서버, 실시간 뉴스는 첫 공개의 필수 조건이 아니다. 활성화하거나 이를 위한 계정/유료 플랜을 만들지 않았다.

## 사용자 확인과 권장 순서

이미 결정한 도메인 monipick.com·Cloudflare·통계 제외·업무용 이메일·미확인/해외 문서 표시·사진 대신 형태 그림은 재결정할 필요가 없다.

사용자에게 필요한 확인은 다음 두 가지다.

1. 최신 후보의 모바일/데스크톱에서 검색·조건 선택·비교·상세를 직접 보고 디자인과 사용 흐름을 최종 수락한다. 권장: 휴대폰으로 2개 모니터 검색·비교를 한 번 실행한다.
2. 공개 전용 출력물 검증 결과와 남은 미확인 목록을 보고 **해당 SHA의 실제 공개 여부**를 승인한다. 지금은 승인을 요청하거나 공개 작업을 시작하지 않는다.
