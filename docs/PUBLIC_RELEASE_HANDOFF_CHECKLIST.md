# 공개 전 인계 체크리스트 · 2026-10-15

기준 커밋: `c9cbfb78ced4559728003056f72d57dd122a951d` · 브랜치: `codex/monitor-purpose-design`.
이번 문서는 다음 실행 순서를 정리한 준비물이다. 호스팅 계약·배포·공개·색인·광고를 실행하거나 승인하지 않는다.

## 최신 결정과 문서 우선순위

[첫 출시 준비 기준](FIRST_RELEASE_PREPARATION.md)이 공개 후보 범위와 준비 순서의 최신 기준이다. [제품 방향](PRODUCT_DIRECTION_V3.md)은 전체 모니터 구매자를 대상으로 하며, [첫 준비 결과](FIRST_RELEASE_PREPARATION_REPORT.md)는 당시 실제 실행 결과다.

- 해외 제조사 공식 문서 제품도 지역·한국 SKU 미확인·누락·충돌을 표시해 후보에 포함한다. 한국 SKU 확인만을 첫 출시의 필수 조건으로 삼지 않는다.
- 사진은 형태 예시, 반응은 같은 기기의 로컬 이모지, 광고·쿠팡 연결은 비활성으로 시작한다. 댓글과 공개 반응 집계는 후순위다.
- 사용자 결정은 도메인과 최종 공개 승인이다. 호스팅·비용 선택은 아직 확정되지 않았다. 구매·유료 계약·외부 계정 생성은 하지 않았다.
- [진행 현황](SITE_NEXT_STEPS_STATUS.md) 아래 과거 공개 범위 선택 질문은 이력이다. 다시 사용자에게 묻거나 기존 결정을 되돌리지 않는다.
- [SEO/GEO 조사 계획](SEO_GEO_V3_REFERENCE_PLAN.md)의 2026-10-10 당시 웹코드 반영 금지·목업 선택 대기는 이전 단계 설명이다. 현재 구현·로컬 검증을 금지하는 최신 지시로 해석하지 않는다. 출처·불확실성·공개 승인 경계는 유지한다.

자료를 삭제하거나 역사적 보고서를 현재 상태처럼 고쳐 쓰지 않는다. 새 결과는 날짜·커밋과 함께 최신 보고서에 기록한다.

## 로컬에서 완료할 확인

다음은 현재 저장소 기준으로 실행할 수 있다. 테스트 개수는 실제 실행에서 확인하고 이전 수치를 복사하지 않는다.

```sh
git status --short
git branch --show-current
python3 -m unittest discover -s tests -q
npm run test:e2e -- --workers=2
python3 scripts/validate_local_site.py
python3 scripts/build_monitor_v3.py --check
python3 scripts/build_monitor_pages_v3.py --check
python3 scripts/build_monitor_review_links.py --check
git diff --check
```

동시에 두 브라우저 전체 실행을 시작하지 않는다. 테스트가 만든 캡처와 사용자 기존 변경을 구분한다. 원본 data/schema 및 사용자 변경의 보존 hash를 확인하고 해당 작업 파일만 커밋한다.

별도 새 경로에 후보 패키지를 만들 때:

```sh
python3 -m scripts.prepare_launch_preview --output /tmp/connectable-launch-preview-next
```

출력은 새 디렉터리여야 하며 `site/`만 향후 문서 루트 후보이다. `manifest.json`은 밖에 둔다. 기존 `web/index.html`, 이전 목업, 원본 연구 자료, 관리 검토 화면을 배포 루트로 올리지 않는다. 이 명령은 서버 실행·업로드를 하지 않는다. 임시 경로의 보존을 전제로 삼지 않고 필요할 때 재생성한다.

## 도메인 결정 후 실행 순서

| 단계 | 실행·확인 | 통과 기준 | 현재 상태 |
| --- | --- | --- | --- |
| 1 | 도메인·호스팅·월 비용 상한·접근 제한 방식 정리 | 실제 계약 비용과 운영 권한 확인. 무료 한도나 보안을 추측하지 않음 | 선택 대기 |
| 2 | 접근 제한된 후보 미리보기 준비 | 인증하지 않은 요청에서 본문·자산·직접 제품 URL을 읽을 수 없음. HTTPS 확인 | 미실시 |
| 3 | 실제 응답·경로 검사 | root가 현재 비교 디자인, 알려진 상세/가이드가200, 존재하지 않는 경로가404. SPA 홈200 대체 응답 금지 | 호스팅 이후 |
| 4 | 접근 제한·보안 헤더 확인 | 호스트에서 CSP, nosniff, referrer 정책, 프레임 차단 적용 여부 확인. 원본 연구·manifest·디렉터리 목록 노출 없음 | 호스팅 이후 |
| 5 | 후보의 최종 화면과 데이터 검토 | 데스크톱·모바일·키보드·오류 상황 및 노출 필드/출처/지역 표시 확인. 대표 비교와 모든 제품 경로 검사 | 실제 URL 확인 대기 |
| 6 | 사용자 최종 공개 승인 | 후보 커밋·URL·남은 미확인·공개 페이지 목록을 명시한 승인 | 보류 |
| 7 | 승인된 공개 URL의 색인 준비 | production origin 확정, canonical·내부 링크·sitemap 일치. 승인 페이지에서만 noindex 정책 변경 | 보류 |
| 8 | 공개 후 실제 응답과 검색 도구 검증 | 실제 URL에서 HTML/헤더/404/모바일 다시 검사, 소유 확인·수집·색인을 각각 기록 | 보류 |

접근 제한 미리보기도 현재 사용자의 실제 공개 금지 범위와 호스팅 계정 권한을 먼저 확인한다. 현재 작업에서는 만들지 않는다. `noindex`와 robots는 인증을 대신하지 않는다. 로컬 `serve_mockup.py`의 헤더가 외부 호스트에 자동 복사된다고 가정하지 않는다.

### 호스팅 후 반드시 확인할 세부 항목

- 선택한 origin의 HTTP→HTTPS 및 루트/상세 URL 이동이 순환하지 않는지 확인한다. 정확한 제품 URL과 trailing slash 정책을 함께 기록한다.
- 존재하지 않는 제품, 자산, 디렉터리 요청에 실제404를 반환한다. 후보 패키지 밖 파일·숨김 파일·이전 관리 화면을 제공하지 않는다.
- CSP는 현재 외부 스크립트·API·프레임이 없는 구조를 기준으로 시작한다. 광고/API가 없는데 편의상 `unsafe-inline`, 광범위 외부 도메인을 허용하지 않는다. 호스트별 설정은 실제 HTML·자산 요청으로 검증한다.
- 미리보기의 HTML과 HTTP 헤더에 상충하는 색인 정책이 없는지 확인한다. robots 차단 때문에 noindex를 읽지 못하는 구성은 피한다. 접근 통제는 별도로 유지한다.
- 공개 승인 후 제품·가이드는 실제 고유 URL을 canonical로 사용한다. 목록의 검색/필터/임의 비교 상태는 초기에 색인 대상에서 제외하고 무차별 조합 페이지를 생성하지 않는다.
- sitemap은 승인된 안정적인 페이지 목록만 포함한다. 빌드 날짜를 근거 재확인일이나 매일 새 `lastmod`로 바꾸지 않는다. 도메인 미정 상태에서는 canonical·sitemap의 운영 URL을 만들지 않는다.
- 반환 HTML의 제목·H1·핵심 사양·출처·미확인 조건과 JSON-LD를 대조한다. 가격·재고·가짜 평점·전체 참여 수를 생성하지 않는다.

## 공개 상태와 사실 상태를 분리

페이지가 공개됐다는 이유로 `public_status=UNKNOWN`, 부분 검토, 미확인 SKU 또는 호환성 승인 보류를 바꾸지 않는다. 제품 후보 포함은 개별 fact 검토 완료나 한국 SKU 동일성의 증명이 아니다. 검증기는 링크·형식·근거 참조·일부 모순을 검사하며 실측 성능이나 실제 기기의 호환성을 보장하지 않는다.

공개 전에는 노출 필드가 공식 근거·검토 계약을 만족하는지 확인한다. 확인한 해외 수치는 문서 지역으로 표시하고, 미확인 값은 미확인으로, 충돌은 충돌로 유지한다. 근거 없는 수치를 지역 안내만 붙여 공개하지 않는다. 단일 후기를 제품 보증·추천 순위·전체 만족도로 승격하지 않는다.
