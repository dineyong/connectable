## 복잡도 증가와 한계

- 작성자는 하나의 CSV 행 대신 노드·포트·간선·구성·시도·관측·근거 ID를 관리해야 한다. 반복 입력과 ID 실수가 늘어난다.
- 부분 경로를 허용해야 추정 없이 수집할 수 있다. 따라서 그래프 형태라는 이유만으로 경로의 완전성이나 규격 호환성을 계산하면 안 된다.
- sequence와 실제 날짜를 분리해 정확성은 높이지만 정렬과 연표를 읽기 어려워진다. 현재는 표현 순서이고 실제 시도 순서는 RECONSTRUCTED_PARTIAL/UNORDERED일 수 있다.
- 중간 시도와 비교 환경이 늘어나 한 게시물의 수정이 많은 줄로 보일 수 있다. JSONL 한 줄은 Git diff 가독성이 낮다.
- 객체 단위 evidence_refs는 그룹 필드를 같은 근거에 묶는다. 필드별 주장의 정밀한 수정 이력까지 제공하지는 않는다.
- 내장/외장 포함 범위와 mirrored 정의가 새 검수 부담이다. “모니터 2개 정상”으로 독립 확장 2개를 생성하면 안 된다.
- 영상과 전원 흐름 방향이 다를 수 있다. 최소 전원 표현은 조건·관측 중심이며 상세 PD 협상 그래프는 지원하지 않는다.
- 구조 검사만으로 작성자 본인의 보고, 명시적 최종 포기, 실제 모델 동일성, 인과관계 또는 개인정보 부재를 증명할 수 없다.

## CSV 유지와 JSONL 전환 비교

| 방식 | 장점 | 단점 | 권고 용도 |
| --- | --- | --- | --- |
| 기존 CSV의 JSON 셀 확장 | 한 행 한 사례, 기존 도구 유지, 스프레드시트로 목록 보기 쉬움 | 중첩 따옴표와 긴 셀, 분기·시도·근거 교차참조를 검수하기 어려움 | v1 기록 보존과 단순 목록 |
| 여러 정규화 CSV | 기기/간선/시도/관측 표를 각각 필터·정렬 가능 | 파일 간 외래 키·동기화·삭제/중복 검증이 늘어남. 사례 하나를 보려면 여러 파일을 결합 | 향후 분석용 파생 테이블 |
| JSONL 한 줄 한 사례 | 중첩 구조와 자료형을 자연스럽게 보존. 스트리밍 처리·JSON Schema 검증 가능 | 원시 diff와 수동 편집이 어려움. 스프레드시트에서는 바로 비교하기 어려움 | **채택 후 원본 저장 형식 권고** |
| 사례별 pretty JSON | 사람과 Git diff가 읽기 쉬움 | 파일 수와 검색·집계 비용 증가, 동일 스키마 버전 관리 필요 | 복잡 사례의 검수용 임시 뷰 |

추천은 **JSONL을 v2 원본으로 두고 CSV 요약표를 필요할 때 파생하는 방식**이다.
별도 연결 구성 파일을 중복 원본으로 저장하지 않고 각 JSONL 레코드 안의 configurations에 포함한다.
이번에는 JSONL 5건과 Markdown 검수표만 생성했다. CSV 파생 도구·관리 UI는 구현하지 않았다.
채택 전까지 v1 CSV가 기존 20건의 기준 데이터다.

## 기존 20건 전체 마이그레이션 예상 난이도

아래 분류는 기존 파일럿의 요약을 바탕으로 한 설계 평가다. 15건은 아직 변환하지 않았으며
원문 재확인에 따라 난이도와 세부 구성 수가 달라질 수 있다. 새 수치나 규격을 채울 계획을 뜻하지 않는다.

| 난이도 | 사례 | 수 | 필요한 검수 |
| --- | --- | ---: | --- |
| 낮음 | UQ-0014, UQ-0024, UQ-0025 | 3 | 질문/구매 전 구분, 미해결 상태와 목표·현재 상태 분리. 경로 미상을 그대로 유지 |
| 중간 | UQ-0006, UQ-0008, UQ-0013, UQ-0015, UQ-0017, UQ-0019, UQ-0020, UQ-0023 | 8 | 변환 장치·해상도/HDR 조건·댓글 근거·최종 조치 확실성 검수 |
| 높음 | UQ-0007, UQ-0009, UQ-0010, UQ-0011, UQ-0012, UQ-0016, UQ-0018, UQ-0021, UQ-0022 | 9 | 분기·복제·재발·내장 화면·다수 대안과 시간축을 수작업으로 분리 |

대다수 필드는 기계적 이동이 가능해도 **배선 간선, 실제 시도 순서, 근거 위치, 독립 확장 수는 자동 확정하기 어렵다**.
현재 5건도 원본 요약을 이용한 구조 검증용이다. 전체 이전 전에 원문을 허용된 방식으로 다시 확인해야 할 사례를
선별하고, 추가 확인이 불가능하면 더 상세한 부분을 미상으로 유지해야 한다.
모델명·날짜·규격을 원문에 없는 값으로 보강하여 변환을 완성하지 않는다.

## 100건 수집 전 반드시 적용할 변경 — 채택 시 제안

1. 사례 유형과 목표/관측의 구분을 수집 양식에 넣는다. 구매 예정 장치를 실제 사용 장치로 기록하지 않는다.
2. 구성 ID와 시도별 관측·근거 연결을 도입하고, 분기를 기계가 구분할 수 있게 한다. 미상 구간 허용은 필수다.
3. 실제 시도 순서와 표현 순서, 게시일·확인일·실제 관측일을 구분한다. 타인의 조언은 실제 조치로 올리지 않는다.
4. 화면 수의 물리 연결·점등·독립 확장·복제 및 내장 포함 범위를 정의한다. 최종 대수만으로 성공을 판정하지 않는다.
5. 기존 결과 코드 유지, 명시된 최종 실패/포기만 FAILURE, 지속성·재발을 별도 관측 상태로 기록하는 기준을 승인한다.
6. v1/v2 기준 파일과 재사용 승인 기준을 명시한다. 공식 사양은 별도 데이터셋, 연결 후보는 자동 확정 금지다.

이번에는 위 변경을 기존 수집 지침·DECISIONS에 적용하지 않았다. 제안 승인 전 21~100번 수집을 재개하지 않는다.

## 최종 채택 권고와 남은 결정

**v2 핵심 구조의 조건부 채택을 권고한다. 현재 파일은 미채택 proposed로 유지한다.**
5건에서 드러난 분기·재발·목표/실제·화면 수 혼동을 해결하므로 같은 v1 형식으로 100건까지 확대하면
나중에 원문 재검수 비용이 더 커질 가능성이 있다. 다만 현 구조 전체를 그대로 필수 입력으로 강제하면
결측이 많은 공개 질문의 작성·검수 부담이 커진다. 최소 입력 필드와 부분 그래프 기준을 먼저 승인해야 한다.

결정할 항목은 다음과 같다.

- JSONL을 채택 후 기준 원본으로 할지, CSV를 병행할지와 기준 파일의 우선순위
- sequence의 표현 순서/실제 순서 분리 및 부분 재구성을 허용하는 검수 규칙
- mirrored를 복제 그룹 전체 물리 대수로 정의하고 확장 수와 배타적으로 셀지
- 포기한 개별 구성의 종결을 별도 객체로 만들지, 현재처럼 관측 summary로 남길지
- 객체별 근거로 충분한지, 필드별 근거 ID가 채택 전에 필요한지
- 장기 사용 유형 기준과 판매 링크 동반 실사용 글의 포함 경계

기존 의사결정을 변경하거나 채택 승인을 자동으로 부여하지 않았다. v1의 20건 전체 변환은 별도 작업이다.

검증기는 국소 ID·참조·영상 순환·완전 경로의 고립 화면·범위를 벗어난 포트/화면·목표와 관측의 역할·잘못된 대수·재발 참조·
결과/종결 불일치·타인 조언 전용 근거·부적절한 승인 상태를 거부한다.
날짜·URL·enum·타입·누락·JSON 중복 키·비유한 수·행 오류 위치도 테스트한다.
비밀값 검사 중 검출 정규식 자체의 private-key 문자열이 오탐돼 헤더 문자 패턴을 좁혔고, 실제 키 헤더 형태를 잡는 회귀 검사를 추가해 재검증했다.
원문 진위·의미상 중복·실제 작성자 역할·최종 실패 주장의 진위는 자동 검사가 증명하지 않는다.
