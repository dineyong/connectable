# 의사결정 기록

## ADR-001: 앱보다 데이터와 판정 규칙을 먼저 구축한다

- 날짜: 2026-10-07
- 상태: 승인

### 결정

UI와 제품 코드를 만들기 전에 서비스 범위, 출처 정책, 데이터 구조,
호환성 판정 규칙과 초기 검증 데이터를 준비한다.

### 이유

사이트의 경쟁력은 화면 디자인보다 판정의 정확성, 근거의 추적 가능성,
실사용 데이터 축적에서 발생한다.

## ADR-002: MVP는 Apple Silicon 맥북과 외장 모니터로 제한한다

- 날짜: 2026-10-07
- 상태: 승인

### 결정

최초 버전은 Apple Silicon MacBook Air와 MacBook Pro의 외장 모니터
연결 문제에 집중한다.

### 이유

제품군을 제한해야 공식 사양과 실제 사례를 충분히 검증할 수 있다. 전체
Windows 노트북까지 동시에 지원하면 모델 변형과 포트 사양 불확실성 때문에
초기 판정 품질이 떨어진다.

## ADR-003: AI는 판정자가 아니라 조사·정리 보조로 사용한다

- 날짜: 2026-10-07
- 상태: 승인

### 결정

AI가 생성한 호환성 답변을 직접 공개하거나 데이터베이스의 확정값으로
저장하지 않는다. AI는 출처 후보 수집, 모델명 정규화, 중복 탐지, 설명문
초안에만 사용한다.

### 이유

잘못된 긍정 판정은 불필요한 구매와 서비스 신뢰 하락으로 이어진다.

## ADR-004: 일반 댓글과 구조화된 연결 결과를 분리한다

- 날짜: 2026-10-07
- 상태: 승인

### 결정

질문·대화용 댓글과 성공·제한·실패를 기록하는 구조화된 사용자 사례를
별도 데이터로 운영한다.

### 이유

자유 형식 댓글만으로는 제품 모델과 연결 조건이 빠져 판정 근거로 재사용하기
어렵다.


## ADR-005: 사용자 질문 코퍼스 기반과 본 수집을 분리한다

- 날짜: 2026-10-07
- 상태: 조사 설계 기록 (공개 판정 승인 아님)

### 결정

기존 범위·등급·판정 상태를 유지한다. [질문 스키마](QUESTION_CORPUS_SCHEMA.md)와
[수집 지침](QUESTION_COLLECTION_GUIDE.md)을 정의하고, 본 수집 CSV는 헤더만
유지한다. 실제 공개 사례 5건은 별도 example CSV에 기록한다. 이번 영어
사례는 한국어 질문 100건 목표에 포함하지 않는다.

### 이유와 제한

디스플레이와 연결 장치는 JSON 배열로 CSV에 저장하여 여러 화면과 경로를
손실 없이 표현한다. 사용자 관측 결과와 공식 호환 판정을 구분한다.
정규화는 원문 표기 정리이며 사양 확정이 아니다. 공식 대조·사람 검수 전에는
판정 재사용을 승인하지 않는다. 조사 결과와 검증은
[기반 작업 기록](QUESTION_CORPUS_FOUNDATION_REPORT.md)에 남긴다.

## ADR-006: 질문 코퍼스 v2를 JSONL 기준으로 채택한다

- 날짜: 2026-10-07
- 상태: 승인 (사용자 명시적 채택, 호환성 판정 승인과 별개)

### 결정

1. [정식 v2 JSON Schema](../schemas/user-question-v2.schema.json)와
   [v2 JSONL](../data/research/user_questions_v2.jsonl)이 활성 기준이다.
   JSONL이 유일한 코퍼스 원본이며 CSV는 필요할 때 생성하는 파생 요약으로 직접 수정하지 않는다.
2. 부분 경로와 부분 순서 재구성을 허용한다. `topology_completeness`, `sequence_basis`,
   객체별 `evidence_refs`로 불확실성을 유지한다. 필드별 claim registry는 후순위다.
3. `mirrored`는 복제 그룹 전체 물리 화면 수다. `independent_extended`와 중복 계산하지 않는다.
4. `LONG_TERM_REPORT`는 작성자가 사용 기간 또는 지속 사용을 명시했을 때만 부여한다.
5. 판매·제휴 링크가 있어도 구체적인 본인 사용 과정과 결과가 확인되면 포함할 수 있다.
   판매·제휴·광고성 여부와 포함 근거를 `review.commercial_context`에 기록한다.
   상품 소개·판매 유도가 중심이며 실사용 근거가 부족한 자료는 제외한다.
6. FAILURE 목표 비율은 없다. 작성자의 명시적인 최종 실패 또는 사용 포기 근거가 있을 때만 분류한다.
7. 사용자 관측과 공식 제조사 사양은 별도 데이터셋으로 유지한다. 모델 문자열만으로 공식 지원을 확정하지 않는다.

### 구성별 결론

선택 배열 `configuration_conclusions`를 도입한다. 각 항목에는 `configuration_id`, `status`,
`termination_type`, `evidence_refs`, 짧은 `summary`를 저장하고 `observation_ids`는 선택이다.
게시물 `outcome`과 독립적이며 한 구성의 포기로 전체 게시물 결과를 자동 변경하지 않는다.
FAILURE는 해당 구성·종결 유형을 명시한 `evidence.author_configuration_terminations`와
작성자 역할의 연결이 있어야 한다. 무신호·답변 부재·타인의 조언만으로 만들 수 없다.
전체 outcome의 FAILURE 역시 별도의 `evidence.author_case_termination`이 필요하다.
이 구조는 명시 진술의 기록을 강제하며 진술의 진위는 원문을 읽는 사람 검수로 확인한다.

### 기록 보존과 적용 범위

제안 스키마와 5건 예시는 각각 `schemas/archive/`, `data/research/archive/`로 이동하여
바이트 그대로 보존한다. archived proposed는 기준 파일이 아니다. 제안서·이전 마이그레이션 보고서는
채택 전 역사 기록으로 유지하고 정식 기준 링크를 표시한다.
v1 CSV·Schema·검증기·테스트는 기존 경로에서 보존한다. v1 CSV는 직접 수정하지 않는 과거 기록이다.

이번 적용은 기존 5건의 정식화만 수행한다. 나머지 15건 이전, 21~100번 수집, 공식 사양 대조,
호환성 판정, 웹사이트/UI, main merge는 수행하지 않는다. 기존 MVP 범위와 승인 정책은 유지한다.
[정식 스키마 문서](QUESTION_CORPUS_SCHEMA_V2.md)와 [수집 지침 v2](QUESTION_COLLECTION_GUIDE_V2.md)를 따른다.

## ADR-007: 사용자 요청에 따라 조사 기반 사이트 목업을 제작한다

- 날짜: 2026-10-07
- 상태: 승인 (사용자의 사이트 목업 완료 요청)

기존 UI 보류는 이번 명시적 요청에 한해 해제한다. 공식 데이터와 판정 규칙 구축 전에는
운영 판정 엔진을 만들지 않고 한국어 반응형 목업을 제작한다. 연결 입력은 확인 필요 항목만 보여주며
기기 선택 옵션은 제품 사양이나 지원 조합 목록이 아니다. 최대 해상도·주사율·충전·호환 여부를 추정하지 않는다.

정식 v2 16건의 결과·출처·관측을 읽기 전용 파생 자산으로 표시한다. 사용자 보고 결과를
공식 호환 판정과 구분하고 미대조·C등급 상태를 상세 화면에 표시한다.
목업 입력은 저장·전송하지 않는다. 기존 코퍼스·스키마·MVP 제품 범위는 보존한다.
외부 공개 배포·제휴·결제·main merge는 이번 목업 완료에 포함하지 않는다.
[목업 실행·검증 보고서](SITE_MOCKUP_REPORT.md)를 따른다.

## ADR-008: 목업 추가 보강과 파일럿 이전 완료

- 날짜: 2026-10-07
- 상태: 사용자 추가 진행 요청에 따른 작업 기록

남은 파일럿 4건을 공식 사양 대조와 섞지 않고 정식 v2로 이전하여 총 20건으로 만들었다.
목업의 입력 결과 갱신·접근성·정적 자산 보안·브라우저 회귀 검사를 보강했다.
외부 폰트 요청을 제거하고 전용 로컬 서버와 GitHub 검사 워크플로를 추가한다.
기존 제조사 사양 분리·C등급·호환성 사용 불가·main 보호 원칙은 유지한다.
[3차 검수](QUESTION_CORPUS_V2_MIGRATION_BATCH_3_REPORT.md)와 [사이트 보강 검수](SITE_HARDENING_REPORT.md)를 기준으로 확인한다.

## ADR-009: 공식 데이터 기반을 사용자 코퍼스와 분리해 착수한다

- 날짜: 2026-10-08
- 상태: 사용자 공식 사양·판정 데이터 구축 선택에 따른 작업 기록

질문 100건 전체 수집 전, 공식 출처 기반을 별도 병행 단계로 진행한다.
기존 질문 20건·v1·v2 스키마와 사용 불가 상태는 유지한다.
공식 출처 A등급과 최종 사람 검수 승인을 구분하고, 초기 두 MacBook Air 모델의
화면 수 규칙은 검수용 후보로만 구현한다. 사이트 공개 판정은 UNKNOWN을 유지한다.
[공식 기반 문서](OFFICIAL_DATA_FOUNDATION.md)에 기준 파일·조건·결측과 후속 순서를 기록한다.
