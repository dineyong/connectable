## 사용자 승인과 결과

사용자는 모니터 구매자를 위한 사양 비교를 1차 목표로 정하고, 간단한 도움 반응·짧은 댓글을 보조 기능으로 채택했다. 특정 기기 중심 타깃을 해제하고 밝은 비교 화면 목업을 승인했다. [제품 방향 v3](PRODUCT_DIRECTION_V3.md)와 [진행 계획](MONITOR_COMPARISON_V3_ROADMAP.md)을 새 기준으로 작성했다.

README 상단에 새 정의·현재 기준·목업·진행바를 추가했다. PROJECT_SCOPE/PROJECT_INSTRUCTIONS/PRODUCT_DIRECTION_V2에는 현재 방향이 바뀌었음을 표시하고 본문을 보존했다. DECISIONS에 ADR-015를 추가했다. 승인 이미지 시안은 [별도 PNG](design/monitor-comparison-v3-concept.png)로 저장했다. 이미지의 제품·수치는 실제 데이터가 아니다. 원본 생성 이미지는 삭제하지 않았다.

## 진행 현황

`■□□□□□` — 단계 완료 1/6. 작업량 비율이나 운영 사이트 완성도 백분율이 아니다.

1. 방향·목업 확정: 완료.
2. 비교 데이터 계약: 다음 작업.
3. 새 탐색·상세·2~3개 비교 화면: 대기.
4. 도움 반응·짧은 댓글: 대기.
5. 가이드·판매처·광고 준비: 대기.
6. 운영 품질·공개 후보 검토: 대기.

기존 데이터와 로컬 기능을 재사용하되 이를 새 v3 구현 완료로 집계하지 않는다. 기존 연구를 삭제하거나 사람 검토 상태를 바꾸지 않았다. 새 비교 화면을 개발하기 위해 이전 연결 경로 연구를 모두 완료할 필요는 없으며 사용하는 사양의 불확실성은 계속 보존한다.

## 사용자 작업과 보존 검증

작업 시작 시 README/DECISIONS, web/site-v2.js, tests/e2e/content-review.spec.js 및 기존 비추적 검토 문서에 변경이 있었다. README/DECISIONS는 이전 변경을 작업 파일에 그대로 두고 새 방향 변경분만 index에 분리해 커밋했다. 기존 미커밋 내용을 일괄 채택하거나 다른 세션의 코드 변경을 이번 작업으로 기록하지 않았다. ADR-014 로컬 초안은 미커밋 상태로 보존하며 이번 채택은 별도 ADR-015다.

- 시작 시 추적 파일·기존 문서 SHA-256과 대조: 이번에 의도한 방향 문서 5개 외 기존 파일 바이트 보존.
- README 기존 본문 및 DECISIONS 기존 추가 내용 보존, 이번 staged diff에 이전 미커밋 변경 제외 확인.
- staged 문서의 내부 경로·민감값 패턴·`git diff --cached --check`: 통과.
- 새 데이터·스키마·서비스 기능·댓글 서버·호환성 엔진을 구현하거나 변경하지 않음.

문서 변경에 구현을 그대로 따라 하는 새 테스트는 추가하지 않았다. push된 최종 커밋은 기존 전체 Python/브라우저/데이터 계약 CI를 실행한다. 기존 기준은 Python423/브라우저72이며, 로컬의 미커밋 UI 변경에 이 기준을 적용했다고 보고하지 않는다. [브랜치 CI](https://github.com/dineyong/connectable/actions?query=branch%3Acodex%2Fmonitor-comparison-direction-v3)의 실제 실행 결과와 링크는 완료 응답에서 기록한다.

## 남은 결정

댓글의 실제 저장 방식·중복/스팸 억제·검토/삭제 권한·개인정보 운영 방식은 구현 전에 정한다. 계정·제휴 링크·광고 활성화와 main/공개는 별도 검토 단계다. 새 방향 승인과 공식 사양 검토·한국 SKU·실충전·공개 호환성 승인을 혼동하지 않는다.

다음 작업은 기존 모니터6종의 필드·단위·포트 조건·지역 SKU·결측을 매핑하고 비교 데이터 계약을 확정하는 것이다. 근거 없는 사양 보완이나 대량 수집은 하지 않는다. main을 변경·병합하거나 서비스를 배포하지 않았다.
