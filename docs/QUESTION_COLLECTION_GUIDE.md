# 사용자 질문 수집 지침

2026-10-07. [기존 절차](RESEARCH_WORKFLOW.md)와 [스키마](QUESTION_CORPUS_SCHEMA.md)를 따른다.

## 포함과 제외

기기 모델 또는 규격, 연결 장치 또는 모니터 일부, 원하는 결과·증상,
실제 연결·구매 의도가 확인되는 공개 사례를 포함한다. MVP 분석은 Apple
Silicon MacBook Air/Pro에 집중한다. 한국어 질문 100건 목표는 유지하며,
영어 example 5건은 형식 검증용으로 별도 집계한다.

모델과 문제가 모두 불명확한 글, 광고, 복제본, 개인정보 제거가 불가능한
자료, 비공개·로그인 제한 자료는 제외한다. 검색 결과 요약만으로 입력하지
않고 공개 본문을 확인한다. CAPTCHA·차단·로그인 우회, 비공개 API,
대량 크롤링을 금지한다. 접근 실패는 그대로 기록하고 다른 공개 출처를 찾는다.

## 수집 순서

1. 공개 본문을 읽고 원문 URL, 원글/댓글 위치, 게시일, 확인일을 기록한다.
2. 사용자명·실명·이메일·전화번호·주문번호·일련번호를 제거한다.
3. 전체 원문·댓글·스크린샷 복제 없이 모델, 연결 조건, 증상과 결과만 요약한다.
4. 모델 표기를 정리하고 확실성을 표시한다. 칩·출시 연도·화면 크기를 추정하지 않는다.
5. 원글 작성자의 결과와 다른 사람의 댓글 결과를 구분한다. 타인의 해결책은
   원글 작성자가 실제로 시도했다고 확인될 때만 attempted_solutions에 넣는다.
6. 공식 사양·표준·독립 실사용을 단계적으로 대조한다. 이번 example은 이 단계 전이다.
7. 등급과 결측 경로, 충돌, 검토 메모를 작성하고 검증기를 실행한다.
8. 사람이 중복·모델·출처·개인정보를 검수한 뒤 승인한다.

## 중복과 불확실성

게시물 URL의 추적값을 제거하고 원문 위치와 구성·증상으로 중복을 확인한다.
재게시나 동일인의 반복 보고는 새 독립 사례가 아니다. 같은 스레드의 다른
작성자·다른 구성은 별도 사례가 될 수 있으나 실제 독립성은 검수해야 한다.
좋아요·동의 버튼·댓글 수를 독립 사례 수로 세지 않는다.

정확한 모델이 확인되지 않으면 identity_certainty=PARTIAL 또는 UNKNOWN,
미상 값은 빈 셀/키 생략 또는 상태 UNKNOWN, missing_fields에 경로를 기록한다.
원문에서 14인치 2021을 M1이라고만 부르면 칩을 M1 Pro로 바꾸지 않는다.
공식 모델 검수 전 공개 판정 대상에서 제외한다.

## 결과와 근거

단일 커뮤니티 사례는 C등급이며 호환성 확정 판정으로 사용하지 않는다.
공식 지원 커뮤니티도 일반 사용자의 글은 공식 사양이나 공식 답변이 아니다.
공식 자료와 실제로 대조하여 충돌하면 official_alignment 및 conflict_status를
CONFLICT, review_status를 NEEDS_REVIEW로 기록하고 사용 승인 여부는 NO로 둔다.
공식 비교 전에는 NOT_CHECKED 및 UNKNOWN을 사용한다. 실패·미해결을
공식적으로 연결 불가능하다는 결론으로 바꾸지 않는다.

소프트웨어·케이블·포트·주사율·해상도·전원·클램쉘 조건이 빠졌다면 같은
조합의 최대 성능을 추정하지 않는다. 과거 OS의 성공은 현재 OS에서의 보장이 아니다.
