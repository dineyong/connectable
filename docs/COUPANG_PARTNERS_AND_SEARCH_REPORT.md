# 쿠팡파트너스 연동 준비 및 모니터 검색

2026-10-11 · 작업 브랜치 `codex/monitor-purpose-design`.

## 공식 문서 확인

로그인된 Chrome의 API 화면에서 키 발급 상태만 확인했다. 계정·키 값은 보고서/코드/스크린샷에 저장하지 않았다. 공개 문서는 별도 브라우저에서 아래 본문 전체를 읽었다. 약관 동의나 계정 변경은 수행하지 않았다.

- [이용약관](https://partners.coupang.com/#help/terms): 2026-09-07 적용, 제1~22조 및 부칙. 같은 화면의 오픈 API 서비스 이용약관 제1~8조와 부칙(2021-04-03)도 확인.
- [운영정책](https://partners.coupang.com/#help/operating-policy): 2026-09-07 적용, 제1~7절 및 부칙.
- [파트너스 API 가이드](https://partners.coupang.com/#help/open-api): HMAC 서명과 deeplink 예제 확인. 모든 API endpoint 문서 전체를 읽었다는 의미는 아니다.
- [다이나믹 배너 가이드](https://partners.coupang.com/#help/tag-usage-guide): 웹/WebView 사용 및 허용 크기 옵션 확인.

## 사이트 적용 결정

사용자 요청에 따라 쿠팡 상품 링크 생성은 **쿠팡파트너스 API**를 사용한다. 판매자용 WING API와 혼동하지 않는다. 공식 사양·뉴스의 원문 링크는 기존 출처 링크를 유지한다.

API는 서버에서 HMAC 인증하며 키를 브라우저에 넣지 않는다. [deeplink 클라이언트](../scripts/coupang_partners.py)는 공식 예제의 POST 경로를 사용한다. `COUPANG_PARTNERS_ACCESS_KEY`, `COUPANG_PARTNERS_SECRET_KEY` 환경변수를 요구하며 응답/키를 파일로 저장하거나 출력하지 않는다. 고정 API 호스트, HTTPS, 리다이렉트 거부, 제한된 응답 크기, 원본 URL과 변환 결과 매칭을 검사한다. 아직 실제 키 설정·실호출·프런트 구매 버튼 연결은 하지 않았다. 현재 정적 미리보기 서버는 구매 API endpoint를 제공하지 않는다.

API 약관 제5조 3항에 데이터 복제·저장·전송 제한이 있으므로 응답을 Git/제품 카탈로그에 축적하지 않는다. 실제 상품 정보 표시·캐시 허용 범위는 API별 조건 또는 파트너스 문의로 확정해야 한다. 공식 제품 사양의 대체 근거로 사용하지 않는다.

## 옆 배너 설치 방법

1. 실제 광고를 노출할 사이트 주소를 파트너스 미디어로 등록한다(운영정책 2절).
2. 파트너스의 다이나믹 배너 메뉴에서 배너를 생성하고 발급된 태그/배너 ID를 확보한다. API 키와 배너 ID는 서로 다르다.
3. 공식 태그가 `ads-partners.coupang.com/g.js`를 불러오고 iframe을 생성한다. 가이드의 샘플 ID는 사용하지 않는다.
4. PC 오른쪽 사이드 영역에 배치하고 모바일에서는 본문 흐름 안으로 이동한다. 비교 버튼과 충분히 떨어뜨린다. 본문을 덮거나 따라다니며 클릭을 유도하는 배너, 커버형 배너는 만들지 않는다(운영정책 4.1).
5. 경제적 이해관계를 눈에 잘 띄게 고지한다(이용약관 제12조 4항). 실제 적용 문구는 최신 대가성 문구 가이드와 대조한다. 공식 광고 내용/링크를 임의 변경하지 않는다.
6. 허용된 배너 크기에 맞게 container를 만들고, 광고 endpoint만 CSP에 최소 허용한다. 광고 실패가 검색·비교를 막지 않도록 한다. 자동 테스트는 광고 요청을 mock하고 광고를 실제 클릭하지 않는다.

이 단계에서는 사이트 등록 여부·최종 도메인·본인 배너 ID가 확인되지 않아 광고 태그를 활성화하지 않았다. 배너는 API 키 없이 공식 생성 태그로도 설치할 수 있다. 수익률이나 수익 발생은 보장하지 않는다.

사용자가 준비할 것: 최종 도메인/미디어 등록 여부, 생성한 배너 ID 또는 코드, 서버측 비공개 키 설정. 키를 채팅이나 공개 저장소에 붙여넣지 않는다. API 화면 열람 중 키가 도구 출력에 포함되었으므로 노출 범위 검토 및 키 변경 문의를 권고한다. 새 키 생성/변경은 사용자가 직접 처리한다.

## 검색 구현

기존 모델 검색을 [검색 모듈](../web/monitor-search.js)로 확장했다. 모델명 공백·하이픈·대소문자를 정규화하며, `27인치 QHD`, `4K IPS`, `144 Hz`, `USB-C` 등 여러 조건을 AND로 검색한다. 기존 브랜드/세부 필터와 교집합으로 동작한다. 크기와 주사율은 정확한 숫자를 비교하고 범위는 기존 필터로 선택한다. 확인되지 않은 필드는 검색용 사양으로 채우지 않는다. USB-C 검색은 영상 입력 확인을 뜻하며 PD 충전 확인으로 확대하지 않는다.

기존 원본 데이터·사용자 변경사항·목업과 main은 보존한다. 새로운 검색과 API 클라이언트만 추가했다. 공개 배포는 하지 않는다.

## 사용자 확인 및 검증

사용자는 최종 도메인이 없고 파트너스에 사이트를 아직 등록하지 않았다고 확인했다. 따라서 현재 광고 활성화는 미등록 미디어 노출을 피하기 위해 보류한다. 도메인 확정 후 등록 및 배너 생성 순서로 진행한다.

첫 브라우저 실행에서 검색 스크립트 HTML 연결 누락으로 실패가 발생했다. 실행을 중단하고 script 연결을 추가한 뒤 전체 검사를 재실행했다. 실패 테스트를 삭제하거나 완화하지 않았다.

- Python 전체: 556개 통과.
- 검색 및 API 테스트는 가상 키와 mock API 응답만 사용. 실 API 인증/권한/응답은 아직 미검증.
- 수정 후 전체 브라우저: 174개 통과(로컬 사용자 테스트 14개 포함).
- 정적 페이지 30개 생성 일치, 내부 경로 검사, git diff 공백 검사 통과.
- 스펙 검색의 모바일/데스크톱 결과를 실제 카탈로그 조건과 대조. `27인치 QHD` 결과 11종.
