# 로컬 사이트 품질 검사와 공개 전 체크리스트

작성일: 2026-10-11. 이 문서는 로컬 구현 검사와 사용자 판단이 필요한 공개 전 단계를 구분한다. 검사 통과는 데이터 승인·색인·배포·광고 활성화 승인이 아니다.

## 로컬 자동 검사

실행: `python3 scripts/validate_local_site.py` 및 `python3 -m unittest tests.test_local_site -q`.

표준 라이브러리 HTMLParser로 다음 범위만 검사한다. 이전 목업은 새 metadata 계약을 강제로 적용하지 않는다.

- [새 목록 화면](../web/monitor-v3.html)
- [JavaScript 없이 읽는 목록](../web/monitors/index.html)
- [구매 가이드](../web/guides/monitor-buying.html)
- [테크 소식](../web/tech-news.html)
- `web/monitors/*/index.html` 제품 상세

검사 항목:

1. 한국어 문서 언어, 반응형 viewport, 페이지별 고유 title/description.
2. 명확한 noindex 유지. 운영 주소 확정·공개 승인 전 canonical을 허용하지 않는다.
3. 명시적 HTML href/src의 로컬 파일 존재, 내부 fragment 존재, 중복 ID, 문서 루트 이탈·심볼릭 링크 이탈 차단. URL path는 브라우저 경로에 맞춰 한 번 디코딩한다. 외부 URL에는 접속하지 않는다.
4. JSON-LD 구문 및 현 단계에서 승인되지 않은 offers/aggregateRating/review/reviewRating의 중첩 포함 여부. 별도 객체의 AggregateRating/Rating/Offer/AggregateOffer/Review 타입도 검사하며 타입 배열과 http(s) schema.org 전체 URI를 포함한다. 식별 정보만 있는 Product 객체는 금지하지 않는다. 이를 금지하는 이유는 현재 공개 가능한 가격·평점·구매 인증 후기 계약이 없기 때문이다. 사실성 자체를 자동 입증하는 기능은 아니다.
5. `<base>`와 실행형 URL scheme을 로컬 검사 계약에서 거부한다.

상대 경로, 루트 경로, 한글 fragment, 잘못된 metadata, 경로 이탈, 중복, 가짜 평점 구조에 대한 회귀 테스트를 포함한다. 실제 파일 검증도 동일 함수를 사용한다. 검증 실패 시 경로와 사유를 출력하고 종료 코드 1을 반환한다.

## 다른 검사와의 관계 및 남은 구조적 한계

- JS 실행 후 생성된 링크·댓글 DOM, CSS url/import, srcset, 외부 URL 접근 성공, 콘솔 오류는 이 정적 검사 범위가 아니다. 브라우저 회귀 테스트와 화면 검토가 필요하다.
- JSON-LD 검사는 알려진 속성과 타입을 검사하며 사용자 정의 context·별칭·원격 context를 확장하는 JSON-LD 처리기는 아니다. 새 구조화 데이터 도입 시 승인 근거와 별도 검토가 필요하다.
- HTMLParser는 HTML 표준 문법 전체를 검증하는 도구가 아니다. 이 검사는 정확하게 명시된 위 계약을 확인한다.
- noindex는 접근 통제 수단이 아니다. 로컬 서버는 127.0.0.1 바인딩을 유지한다. preview를 외부에 공개하려면 접근 제어도 별도로 검토해야 한다.
- 현재 `serve_mockup.py`의 HTTP CSP `connect-src 'none'`은 서버 응답 정책이다. HTML meta에서 더 넓게 지정해도 이를 완화하지 못한다. 현재 정적 JS 데이터 파일은 별도 script 요청으로 읽으며, 향후 API fetch나 실제 댓글 저장을 붙일 때 서버 정책·권한·통합 검사를 함께 설계해야 한다.
- 제목·설명 고유성이 정확한 제품 사양, 한국 SKU 동치, 사용 후기 진실성을 입증하지 않는다. 원본/파생 데이터 검증기와 사람 검토는 계속 별도다.
- 일부 metadata·로컬 상태 통과만으로 SEO/GEO 노출이나 수익을 보장하지 않는다.

## 사용자가 관여하기 전 가능한 후속 작업

- 신규 로컬 페이지가 추가될 때 검사 범위와 의미 있는 테스트를 함께 추가.
- 원본 검토 상태를 보존하며 명시적 링크, 모바일 읽기, 키보드 조작, 빈 결과·로드 실패 안내 검증.
- 댓글은 기기 내부 임시 시연과 실제 서버 저장·검토·공개를 명확히 구분.
- 최신 데이터·코드로 전체 Python/브라우저 및 CI 재실행. 당시 결과는 해당 통합 작업 보고서에 기록.

## 공개 전 사용자 판단 필요 — 이번 작업에서 실행하지 않음

| 항목 | 공개 전에 필요한 판단/근거 |
|---|---|
| 운영 도메인·호스팅 | 실제 URL, 배포 환경, 접근·운영 권한과 공개 승인 |
| 공개 데이터 | 제품별 한국 SKU·부분 검토 상태와 공개 범위 확인; UNKNOWN 자동 승격 금지 |
| 색인 정책 | 승인 페이지에 한해 noindex 변경, canonical·sitemap·robots 일관성 및 실제 응답 검사 |
| 댓글 운영 | 저장 방식, 보존 기간, 신고·삭제·검토 책임, 개인정보 고지와 스팸 방지 |
| 광고·제휴 | 계정·링크·정확한 상품 옵션·고지 검토, 활성화 승인 |
| 제품 사진 | 파일별 사용 근거 확보 후 반영. 임의 외부 사진 복제 금지 |
| 뉴스 운영 | 출처 이용 조건 및 운영 갱신 프로세스 확인. 로컬 타이머를 실시간 서비스로 표현하지 않음 |
| 검색 도구 | 실제 도메인 소유 확인·계정 권한·수집 결과 확인 |

원칙은 [제품 방향](PRODUCT_DIRECTION_V3.md)과 [SEO/GEO 참고 계획](SEO_GEO_V3_REFERENCE_PLAN.md)을 따른다. 기존 조사자료와 데이터는 보존한다.
